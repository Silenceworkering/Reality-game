# Запуск и Render

Деплой **не выполнен**, публичного URL нет. Токены в чат не нужны. Для публикации требуется подключение Render с правом создавать сервис и диск и подтверждённый пользователем платный тариф; текущий аккаунт Render недоступен.

Текущий Blueprint — Docker web service + persistent SQLite disk. Не Static Site: фронтенд и API одного origin, поэтому same-origin cookies и нет CORS. Это намеренное отличие от PostgreSQL/Static Site Blueprint в исходном ТЗ. Не масштабировать горизонтально.

1. В Render создать Blueprint из Silenceworkering/Reality-game, проверить актуальные условия starter/disk и стоимость.
2. ORIGIN — точный HTTPS URL без завершающего слеша, COOKIE_SECURE=true.
3. DATABASE_PATH=/app/data/game.sqlite, постоянный диск /app/data обязателен. Без диска потеряется прогресс при пересоздании контейнера.
4. Проверить /health, создать аккаунт, пройти покупку и reload, перезапустить сервис и повторить вход.
5. Схема создаётся при первом старте. Это не миграционная система: перед изменением схемы нужен backup + версионная миграция.

Бэкапы: использовать SQLite backup API либо остановить сервис и сохранить весь каталог data (включая WAL/SHM). Нельзя копировать только активный .sqlite-файл обычным cp. Хранить шифрованно вне диска сервиса, установить retention, проверить восстановление на отдельном экземпляре. В текущем Blueprint автоматический backup не настроен.

Rollback: остановить записи, восстановить backup в отдельный каталог, проверить integrity_check/foreign_key_check, развернуть совместимый предыдущий commit и переключить диск только после проверки. Секреты/БД/пароли не коммитить. Мониторинг и error reporting не подключены. Условия Render и цены из этого окружения не проверялись.
