# Бесплатное размещение: Render + Neon

Render Blueprint использует plan: free, Node.js 24 и **не содержит платных дисков**. Neon-проект создаётся в free-организации; приложение получает DATABASE_URL только в серверное окружение. Никогда не коммитить строку подключения.

## Запуск

1. В Neon Free создать отдельный проект/базу для игры (не использовать БД другого приложения).
2. Создать Render Free web service из main этого репозитория, регион Frankfurt.
3. Build: `npm ci && npm run check && npm run build`; start: `npm start`.
4. NODE_VERSION=24.19.0, COOKIE_SECURE=true, DATABASE_URL — строка Neon, предпочтительно pooled. ORIGIN можно не задавать: на Render сервер использует RENDER_EXTERNAL_URL. Для другого хостинга ORIGIN обязателен с точным HTTPS URL.
5. Проверить /health: storage=postgresql. Данные и сессии находятся в Neon и переживают замену контейнера.

На первом старте таблицы создаются транзакционно в пустой базе. Изменения существующей схемы требуют отдельной миграции: CREATE IF NOT EXISTS не обновляет структуру таблиц. Перед будущими изменениями — отдельная Neon-ветка, тесты, backup и план rollback. Для миграций/pg_dump использовать direct URL; для запросов приложения pooled URL.

## Ограничения бесплатного тарифа

По проверенным 16.10.2026 условиям Render Free засыпает после 15 минут без трафика, пробуждение может занять около минуты. Бесплатные часы общие для workspace, где есть другие сервисы. Автоматического перехода на платный тариф этот проект не настраивает. Neon тоже имеет бесплатные квоты; условия могут измениться. Это размещение прототипа, не обещание бесплатного 24/7 multiplayer.

Не использовать локальную SQLite на Render Free: временная файловая система теряется при остановке/замене контейнера. Бесплатный Render Postgres с истечением срока здесь не создаётся.

## Backup и rollback

Neon Free имеет ограниченную историю восстановления: проверить актуальный retention в Dashboard. Для независимой копии использовать pg_dump через прямое подключение, хранить зашифрованно вне сервиса и протестировать restore в отдельной базе. Автоматические внешние backup и мониторинг пока не настроены. Rollback к старой SQLite-версии не сохраняет Neon-прогресс; использовать совместимую PostgreSQL-версию приложения.

Локальный запуск сохраняет SQLite для разработки без учётных данных. `npm ci && npm start`. Docker Compose — только локальная SQLite-конфигурация; production использует Render native Node.
