# Ну живи

Маленькая жизнь в большом доме. Первая история — «Последний подъезд».

**Работающий одиночный прототип, не публичная многопользовательская бета.** Регистрация, квартира, диалоги и покупки действительно работают на сервере и сохраняются в БД (SQLite локально, PostgreSQL на хостинге). Это начальная реализация этапов 0–1 из ТЗ, с явными отклонениями ниже.

![Игровой двор](docs/preview-desktop.png)

## Запуск

Нужен Node.js **24+**, перед первым запуском установите зависимости:

```sh
npm ci
npm start
# http://localhost:3000
```

Или `docker compose up --build` (Docker-сборка в этом окружении не проверялась). БД создаётся автоматически в `data/game.sqlite`; каталог не коммитится. Никакие внешние API или секреты для локальной версии не нужны. Переменные из `.env.example` передавайте окружением или запускайте `node --env-file=.env apps/server/server.mjs`; автоматической загрузки `.env` нет.

## Что можно пройти

1. Получить ключи: ник 3–24 символа, пароль не короче 10.
2. Познакомиться с Тамарой → спросить о квартире №0 → помочь Мише. Реплики и порядок шагов проверяет сервер.
3. Открыть дом → свой этаж и квартиру. Чужие квартиры недоступны.
4. Купить диван за 2 500 ₽, переместить к окну или кухне.
5. Перезагрузить страницу или войти с другого браузера — деньги, диван и история сохранятся.
6. Открыть журнал разговоров и движений кошелька.

Гостевой просмотр не создаёт аккаунт, не изменяет БД и не даёт покупать или проходить сюжет.

## Проверки

```sh
npm run check
npm test
npm run build
# При наличии Chromium:
node scripts/browser-test.mjs
```

Проверены 5 unit/integration-сценариев и реальный Chromium: регистрация → разговор → дом → покупка → перестановка → перезагрузка. Размеры 1440×900, 390×844, 360×800; без горизонтального переполнения страницы и JS-исключений. Это не тест на реальном iPhone/Android и не нагрузочная проверка. `check` проверяет синтаксис JS, а не TypeScript/ESLint. CI подготовлен; его статус нужно проверить в Actions после загрузки.

## Архитектура и ограничения

Node HTTP + PostgreSQL (pg) или встроенная SQLite + ES modules + SVG. Выбор сделан для запуска и проверки в ограниченном окружении; рекомендуемый в ТЗ React/Phaser/Fastify/Prisma **не реализован**; PostgreSQL поддерживается с версии 0.2. Это основа для замены, не заявление о завершении этапа 0 по всем критериям. SQLite подходит только для одного серверного экземпляра. Хостинг использует PostgreSQL; запись сериализуется advisory transaction lock для текущего небольшого среза.

Квартира выдаётся автоматически, по 36 на дом. Покупка и денежный журнал выполняются одной транзакцией; идемпотентный ключ защищает повтор. Клиент не задаёт цену, пользователя или остаток. Пароли scrypt, токены сессий случайные и хранятся в БД только в виде SHA-256. См. [безопасность](docs/SECURITY.md).

**Пока отсутствуют:** WebSocket/multiplayer, чаты, визиты и приглашения, работы, рынок, бизнесы, аренда/собственность, модерация, полная история квартиры №0, анимации персонажей, звук, финальная рисованная графика, настоящий offline-режим. PWA содержит manifest и service worker без кэширования; установка на iOS отдельно не проверена.

Бесплатное развёртывание: Render Free + Neon Free; DATABASE_URL передаётся только в секреты сервиса. Render засыпает после простоя, действуют квоты аккаунта. Подготовлен одно-сервисный [Render Blueprint](render.yaml) с бесплатным web service и внешней Neon PostgreSQL; актуальные цены необходимо проверить. [Развёртывание](docs/DEPLOY.md), [план](docs/ROADMAP.md), [QA](docs/QA.md).
